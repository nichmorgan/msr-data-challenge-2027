\section{Plan}

All of the team members will share responsibility for study design, implementation, validation, analysis, and writing.
Each member will contribute substantially and review the full pipeline so that all understand the design and its limitations.

\subsection{Responsibilities}
The project responsibilities are dataset profiling, population selection, tool extraction, license identification and freedom grouping, quality checks, analysis of RQ1--RQ3, and preparation of the paper.
The team will document decisions, code, and validation results in the shared repository.

\subsection{Milestones}
\begin{itemize}
    \item \textbf{Before November~3:} Profile GitSkills, decide on filters, prototype tool extraction, and draft license grouping rules.
    \item \textbf{Before December~3:} Complete tool extraction, license discovery, validation, and the RQ1--RQ3
    analyses.
    \item \textbf{Before December~9:} Incorporate feedback, rerun and check the analysis, finalize figures and results, and submit the paper.
\end{itemize}

\subsection{Risks and contingencies}
Repository discovery depends on confirmed tool mentions, and license analysis depends on discovered repositories.
This largest risk for this project is that we will not be able to get satisfactory results from the tool, repository, and license discovery methodology.
In the case of this happening, we will move to a less automated strategy utilizing manual analyses and tools such as the GitHub repository search API\@.
If quality checks fail, the team will revise the relevant settings, rerun the stage, and review remaining gaps manually.
If APIs, repository candidates, or license files are unavailable or ambiguous, unresolved cases will be recorded rather than guessed.
If needed, the team will report a clearly defined subset and explain its effect on the research questions.
